## 简介
本文件面向"hotkey"项目的外部工具集成，围绕以下主题展开：
- Node.js 桥接工具的使用与配置：如何启动、调用与诊断。
- PowerShell 脚本集成机制：浏览器应用模式、RDP 连接与探测、Chrome 系统协议管理、Chrome 配置文件复制。
- 网络控制器（DevTools 网络面板）的自动化能力与稳定性策略。
- 远程桌面支持：本地最小化信号、剪贴板桥接、RDP 模板与连接脚本。
- 工具间通信机制与数据交换格式：HTTP/JSON、WinHTTP、UIA、剪贴板。
- 最佳实践、故障排除与性能优化建议。

## 项目结构
该项目采用"功能模块化 + 工具脚本"的组织方式：
- get-source-panel-line-number：Node.js 桥接，用于从 DevTools 获取当前源码面板行号。
- apps：浏览器应用模式启动脚本（ChatGPT/DMS）。
- lib：UIA 与轻量 JSON 解析库。
- templates：RDP 模板文件。
- rdp.ahk / rdp-connect.ps1：远程桌面自动化与连接脚本。
- OpenControllerFromNetwork.ahk：DevTools 网络面板 URL 复制与解析。
- setup-node-pnpm-lite.ps1 与 nvm-node-pnpm-setup-guide.md：Node/pnpm 环境准备与配置。
- **新增**：PowerShell 脚本集成功能，包括 Chrome 系统协议管理与 Chrome 配置文件复制。
- **新增**：多桌面Chrome配置文件管理，支持按虚拟桌面隔离的调试环境。

## 核心组件
- Node.js 桥接（DevTools 行号获取）
  - 通过 chrome-remote-interface 连接 Chrome DevTools，定位 Sources 面板当前编辑器的选区起始行，暴露 HTTP 接口返回 JSON。
  - AutoHotkey 通过 WinHTTP 发起 GET 请求，解析响应并显示提示。
  - **新增**：支持 PowerShell 启动器，提供更灵活的启动方式。
  - **新增**：增强稳定性机制，包括连续失败自动重启和缓存回退策略。
- 浏览器应用模式（ChatGPT/DMS）
  - PowerShell 脚本生成快捷方式并注入 AUMID，以支持任务视图/开始菜单识别。
  - browser_apps.json 统一描述浏览器路径、公共参数与应用清单。
- **新增**：Chrome 系统协议管理
  - PowerShell 脚本用于管理系统级 Chrome 协议注册，支持查询、启用、禁用三种操作模式。
  - 自动检测系统协议状态，提供安全的协议管理能力。
- **新增**：Chrome 配置文件复制
  - PowerShell 脚本用于复制 Chrome 用户配置文件，支持无执行策略限制的批量操作。
  - 提供配置文件备份与恢复的便捷方案。
- **新增**：多桌面Chrome配置文件管理
  - 支持按虚拟桌面编号复制配置文件到独立的调试目录。
  - 自动处理端口映射和桌面隔离的调试环境。
- 网络控制器（DevTools 网络面板）
  - 基于 UIA 定位网络请求行，优先右键菜单复制 URL，其次回退 Ctrl+C，最后解析 API 路径。
  - 支持性能日志与自适应重试策略。
- 远程桌面（RDP）
  - AutoHotkey 监听剪贴板变化，接收"最小化信号"后在本地最小化 mstsc 窗口。
  - PowerShell 脚本进行主机名解析、MAC/IP 映射、端口探测与 mstsc 启动。
  - RDP 模板集中管理连接参数。

## 详细组件分析

### Node.js 桥接工具（DevTools 行号）
- 功能要点
  - 自动发现 DevTools 目标并建立 CDP 连接。
  - 在 DevTools 内部上下文执行表达式，读取当前源码面板编辑器的选区起始行。
  - 暴露 HTTP 服务，返回 JSON 结构。
  - **新增**：实现连续失败自动重启机制，提升系统稳定性。
  - **新增**：提供健康检查接口，支持服务状态监控。
- 配置与启动
  - 默认监听端口与路径：localhost:3000/line-number。
  - 可通过 VBS 或命令行启动 Node 脚本。
  - **新增**：支持 PowerShell 启动器，提供更灵活的启动方式。
  - AutoHotkey 启动前会检测 Chrome 调试端口与 Node 服务状态。
  - **新增**：健康检查接口 /health 用于服务状态验证。
- 数据交换格式
  - 请求：HTTP GET /line-number
  - 响应：JSON 对象，包含行号或错误信息。
  - **新增**：健康检查：HTTP GET /health 返回 {ok: true, pid: process.pid}
- 热键绑定
  - F10 初始化环境（启动 Chrome 与 Node 服务）。
  - Ctrl+Alt+L 获取行号并提示。
  - Shift+F10 强制重启 Chrome 调试实例。
  - Ctrl+F12 进行全链路诊断（进程、端口、服务）。

### 自动重启机制与稳定性优化
- 连续失败检测
  - 系统维护连续失败计数器，当 CDP 返回 0 时增加计数。
  - 当失败次数达到阈值（默认3次）时触发自动重启。
  - **新增**：重启前返回缓存结果，标记 `_restarting: true`。
- 缓存回退策略
  - 成功获取结果时缓存到最后一次成功结果。
  - 当 CDP 失败但存在缓存时，返回缓存结果并标记 `_cached: true`。
  - **新增**：缓存结果包含原始数据和状态标记。
- 健康检查接口
  - 新增 `/health` 接口提供服务状态检查。
  - 返回包含进程ID的健康状态对象。
  - **新增**：支持端口占用检测和现有服务识别。
- 错误处理与超时控制
  - 改进 HTTP 服务器错误处理，特别是端口占用情况。
  - **新增**：健康检查超时控制（800ms），防止阻塞。
  - **新增**：CDP 连接异常捕获和资源清理。

## 故障排除指南
- Node.js 桥接
  - 症状：Bridge Offline
    - 检查 Node 服务是否启动、端口是否被占用。
    - 使用 Ctrl+F12 进行链路诊断。
    - **新增**：检查 PowerShell 启动器权限与执行策略。
    - **新增**：使用健康检查接口验证服务状态：curl http://localhost:3000/health
  - 症状：Chrome 正在运行但未开启调试端口
    - 使用 Shift+F10 强制重启调试实例。
  - **新增**：症状：服务频繁重启
    - 检查 DevTools 状态和 CDP 连接稳定性。
    - 验证连续失败阈值设置（默认3次）。
    - 查看重启前的缓存回退机制是否正常工作。
- 浏览器应用模式
  - 症状：应用未出现在任务视图/开始菜单
    - 检查 AUMID 是否正确注入。
    - 确认快捷方式保存路径与图标设置。
- **新增**：Chrome 系统协议管理
  - 症状：协议状态查询失败
    - 检查 PowerShell 执行策略设置。
    - 确认管理员权限是否足够。
  - 症状：协议启用/禁用失败
    - 验证系统协议注册表访问权限。
    - 检查防火墙设置是否阻止相关操作。
- **新增**：Chrome 配置文件复制
  - 症状：配置文件复制失败
    - 检查 Chrome 是否正常关闭。
    - 验证目标路径的写入权限。
  - 症状：配置文件损坏
    - 确认复制过程中的文件完整性。
    - 检查磁盘空间是否充足。
- **新增**：多桌面Chrome配置文件管理
  - 症状：桌面编号解析失败
    - 检查参数格式是否正确（支持逗号分隔、空格分隔等多种格式）。
    - 确认桌面编号范围在1-99之间。
  - 症状：端口映射错误
    - 验证桌面编号与端口号的对应关系（桌面N使用端口9222+N）。
    - 检查目标目录是否存在且可写。
- 网络控制器
  - 症状：无法复制 URL
    - 优先右键菜单失败时，检查菜单项名称评分与缓存有效性。
    - 回退到 Ctrl+C 与剪贴板恢复流程。
- RDP
  - 症状：远程最小化无效
    - 确认本地会话与远程会话区分，确保信号正确写入剪贴板。
  - 症状：连接失败
    - 使用安全模式进行 DNS + 3389 探测，确认网络可达性。

### **新增**：Node.js 桥接稳定性机制详解
- 连续失败检测机制

  - 计数逻辑：CDP 返回 0 时增加失败计数
  - 触发条件：失败次数达到阈值时自动重启
- 缓存回退策略
  - 缓存存储：lastResult 存储最后一次成功结果
  - 回退逻辑：失败时返回缓存结果并标记 `_cached: true`
  - 状态标识：`_restarting: true` 标识重启过程
- 健康检查接口
  - 路径：/health
  - 响应：{ok: true, pid: process.pid}
  - 超时：800ms
  - 用途：服务状态验证和端口占用检测
