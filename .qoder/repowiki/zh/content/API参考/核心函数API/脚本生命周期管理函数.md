## 简介

本文档详细介绍了Autohotkey v2项目中的脚本生命周期管理函数，重点分析了`ScriptLifecycle`类的完整接口设计。该类提供了事件驱动的脚本生命周期管理能力，包括初始化、重载、钩子注册和退出处理等功能。

该项目是一个基于Autohotkey v2的热键脚本集合，用于自动化各种应用程序的启动和窗口管理。脚本生命周期管理是整个系统的核心基础设施，确保脚本能够正确地初始化、响应重载请求、执行清理操作并在退出时进行适当的资源回收。

**最新更新**：新增了脚本重载过程中的用户反馈机制，通过工具提示显示"脚本重载中..."状态，同时禁用了自动浏览器缓存重建以防止与UIA_Browser的JSExecute功能产生冲突。

## 核心组件

### ScriptLifecycle类概述

`ScriptLifecycle`类是整个脚本生命周期管理的核心，采用了静态方法设计模式，提供了一个统一的事件驱动架构。该类通过环境变量机制实现脚本重载功能，并支持多种类型的钩子函数注册。

#### 主要特性

1. **环境变量驱动的重载机制**：使用`AHK_SCRIPT_RELOAD`环境变量标记脚本重载状态
2. **事件驱动架构**：支持启动、重载和退出三种生命周期事件
3. **钩子函数注册系统**：提供灵活的回调函数注册机制
4. **自动资源管理**：集成OnExit事件处理程序
5. **用户反馈机制**：在脚本重载过程中显示工具提示通知

#### 环境变量机制

脚本使用`AHK_SCRIPT_RELOAD`环境变量作为重载状态的标记机制：

- **初始状态**：环境变量为空字符串
- **重载标记**：设置为"1"表示脚本正在重载
- **状态清除**：在重载过程中自动清除标记

这种设计避免了使用全局变量，提供了更可靠的跨脚本通信机制。

#### 钩子函数注册系统

系统支持三种类型的钩子函数注册：

1. **启动钩子** (`RegisterStart`)：脚本启动时执行
2. **重载钩子** (`RegisterReload`)：脚本重载时执行  
3. **退出钩子** (`RegisterExit`)：脚本退出时执行

每种钩子类型都有独立的注册表，确保生命周期事件的精确控制。

### 浏览器缓存处理优化

**重要变更**：禁用脚本重载时自动重建浏览器缓存

为了避免UIA_Browser的JSExecute功能在脚本重载过程中产生干扰，系统现在不再自动重建浏览器缓存：

```autohotkey
; 不再在 Reload 时重建浏览器缓存：BuildBrowserCache 依赖 UIA_Browser，其 JSExecute
; 保底会把 "javascript:..." 写入地址栏并发送 Ctrl+L+Enter；在 Ctrl+Alt+R 重载
; （修饰键仍按住、Chrome 在前台）时，这串地址栏内容会被注入/覆盖到当前页面。
; 且 ActivateApp 现以进程级 FindExistingAppWindow 为首选路径，无需该缓存。
; ScriptLifecycle.RegisterReload(BuildBrowserCache)
```

这一变更解决了以下问题：
1. 防止JSExecute代码被意外注入到浏览器地址栏
2. 避免在重载过程中修改当前页面内容
3. 提高脚本重载的稳定性和可靠性

## 性能考虑

### 生命周期优化策略

1. **延迟初始化**：钩子函数在需要时才执行，避免不必要的初始化开销
2. **缓存机制**：使用`hwndCache`全局变量缓存浏览器窗口句柄，减少重复查询
3. **条件过滤**：在重载过程中跳过无意义的隐藏窗口，提高处理效率
4. **用户反馈优化**：使用定时器刷新工具提示，避免阻塞主线程

### 内存管理

- **自动垃圾回收**：利用Autohotkey的自动内存管理机制
- **COM对象清理**：在浏览器自动化完成后及时释放UIA对象引用
- **资源清理**：退出钩子确保所有资源得到正确释放

### 浏览器缓存优化

新的ChromeAppMgr模块采用了更高效的浏览器窗口查找策略：
- 优先使用窗口标题扫描而非进程命令行匹配
- 避免在重载过程中执行耗时的UIA操作
- 提供实时窗口查找和缓存兜底的双重机制

## 故障排除指南

### 常见问题及解决方案

#### 脚本重载失败

**症状**：调用`Reload()`后脚本没有重启

**可能原因**：
1. 环境变量设置失败
2. 重载钩子函数抛出异常
3. 系统权限不足

**解决方法**：
```autohotkey
try {
    ScriptLifecycle.Reload()
} catch e {
    MsgBox "重载失败: " e.Message
}
```

#### 工具提示不显示

**症状**：按Ctrl+Alt+R后没有看到"脚本重载中..."提示

**解决方法**：
```autohotkey
^!r::
{
    ScriptLifecycle.Reload()
    ToolTip("脚本重载中...")
    SetTimer(() => ToolTip(), 1000)
    ; 确保定时器正常工作
    if (A_TickCount - LastTooltipTime < 1000) {
        ToolTip("")
    }
}
```

#### 浏览器缓存相关问题

**症状**：浏览器应用无法正确激活或缓存失效

**解决方法**：
```autohotkey
; 手动重建浏览器缓存
global hwndCache := Map()
BuildBrowserCache()

; 检查缓存状态
for key, hwnd in hwndCache {
    MsgBox "缓存项: " key " -> " hwnd
}
```

#### 钩子函数执行异常

**症状**：脚本启动或重载时出现错误

**解决方法**：
```autohotkey
ScriptLifecycle.RegisterStart(funcWithTryCatch)
ScriptLifecycle.RegisterReload(funcWithTryCatch)
ScriptLifecycle.RegisterExit(funcWithTryCatch)

funcWithTryCatch() {
    try {
        ; 你的代码
    } catch e {
        MsgBox "钩子函数错误: " e.Message
    }
}
```

## 结论

`ScriptLifecycle`类为Autohotkey v2项目提供了强大而灵活的脚本生命周期管理能力。通过环境变量驱动的重载机制、事件驱动的钩子系统和自动化的资源管理，该类确保了脚本能够在各种运行状态下保持稳定和可靠。

### 设计优势

1. **模块化设计**：清晰的职责分离，便于维护和扩展
2. **事件驱动架构**：支持异步处理和回调机制
3. **环境变量机制**：提供可靠的跨脚本通信方式
4. **钩子函数系统**：灵活的扩展点设计
5. **用户反馈机制**：改进的用户体验，通过工具提示提供重载状态反馈
6. **稳定性优化**：禁用有问题的自动缓存重建，提高重载过程的稳定性

### 最佳实践建议

1. **错误处理**：始终在钩子函数中包含适当的错误处理逻辑
2. **资源管理**：确保在退出钩子中清理所有占用的资源
3. **性能优化**：合理使用缓存机制，避免重复的系统调用
4. **用户体验**：在长时间操作中提供用户反馈，如工具提示
5. **测试验证**：在开发环境中充分测试重载和退出流程
6. **兼容性考虑**：避免在重载过程中执行可能影响当前UI状态的复杂操作

该生命周期管理系统为Autohotkey脚本的长期运行和维护奠定了坚实的基础，是现代自动化脚本开发的重要基础设施。最新的工具提示通知功能和浏览器缓存优化进一步提升了系统的稳定性和用户体验。
